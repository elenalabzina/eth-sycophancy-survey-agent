# Prolific human interaction pilot (4 invited participants)

**Research prototype — not yet production validated.** This is a **third, independent mode** of the repository. Existing chat and blind grading remain unchanged. Its purpose is to run one 10-minute, treatment-blinded conversation with each of four previously screened participants, one participant in each developmental-group × policy cell.

## Design
- Four approved returning Prolific participants; recruitment by Custom Allowlist.
- Two provisionally lower, two provisionally higher WUSCT patterns. The developmental categorization is **not an official WUSCT TPR**, and is never sent to the model or participant.
- Within each group, exactly one is randomly assigned Neutral and one Sycophantic; assignments are set in a **private** JSON file before data collection.
- All participants discuss **independent safety testing of advanced AI systems** using the same framing and 10-minute timer.
- Internet search is OFF for both conditions (to avoid differences in retrieved evidence).
- Record baseline and post-conversation attitudes/confidence (0–100), transcript and timestamps in an offline SQLite database. Labels and participant mapping stay **outside public GitHub**.
- The pilot is qualitative/feasibility only: **n=1 per cell does not permit an inferential interaction test**.

## 1. Researcher: local preparation

Clone/pull repository, create the virtual environment and install server dependencies as described in the main README. Keep the Qwen3-14B MLX endpoint running on localhost:8080.

Privately create the file \`private/pilot_assignments.json\` in the repository root:

\`\`\`json
{
  "participants": {
    "PARTICIPANT_ID_1": {"group": "higher", "condition": "neutral"},
    "PARTICIPANT_ID_2": {"group": "higher", "condition": "sycophantic"},
    "PARTICIPANT_ID_3": {"group": "lower", "condition": "neutral"},
    "PARTICIPANT_ID_4": {"group": "lower", "condition": "sycophantic"}
  }
}
\`\`\`

Replace placeholders with your actual 24-character Prolific IDs, and randomize condition **within each group once**, before exposing the study. **Never commit this file or any demographic/participant data.** A prepared private assignment file can be copied directly to the location above.

This mode enforces the four-cell distribution and rejects IDs outside the allowlist.

### Prolific completion link
Create the study draft in Prolific first. Configure an external study URL and obtain the actual completion URL generated by Prolific. Set it as an environment variable before starting the server:

\`\`\`bash
source .venv/bin/activate
export PILOT_ASSIGNMENTS_FILE=private/pilot_assignments.json
export PILOT_COMPLETION_URL="https://app.prolific.com/submissions/complete?cc=YOUR_PROLIFIC_CODE"
python scripts/run_prolific_pilot.py
\`\`\`

The app will run at **http://127.0.0.1:8092/**. Use the actual code and verify the completion redirect in a private end-to-end test. The server refuses to start without the configured completion URL (unless explicitly running a development dry run using \`PILOT_ALLOW_NO_COMPLETION_URL=1\`).

**Do not give participants localhost:8092**: that address exists only on the researcher's machine.

## 2. Provide a secure public HTTPS address

Prolific participants need an accessible HTTPS study URL, while the Qwen model may continue running locally. Configure a narrowly scoped HTTPS reverse proxy/tunnel (such as Cloudflare Tunnel) pointing to localhost:8092, using a researcher-owned domain or configured subdomain. The model's port 8080 must **never** be exposed publicly. Run and test the tunnel, Qwen server, and pilot server throughout participant sessions. This is a network path to the **researcher's local** inference service, not participant-side model hosting.

Production cautions:
- The prototype trusts the Prolific URL ID parameter against the private allowlist, but **does not cryptographically verify** the participant's identity. Consider Prolific's secure external URL/JWT feature where available.
- HTTPS alone is not authentication. Add suitable rate limiting, access control for the study, monitoring, and informed-consent/data-retention review before real recruitment.
- Do **not** expose the local survey preview, transcript APIs, SQLite file, or private assignment file on a public server.
- Responses are only persisted on your local computer. Keep a protected backup and a plan for interruption or power loss.
- An accidental server restart does not erase transcript data, but the inference server and tunnel must be restored. In-progress users can resume from the same browser/token within the remaining time.

## 3. Prolific: invite the four returning participants

1. Create a new study with **4 places** and a duration long enough to allow the full ten-minute chat **plus introductory and final questions**. A 13–15 minute estimate is a reasonable planning starting point, to be tested before launch.
2. In **Recruit participants → Add filters**, select **Custom Allowlist** and paste the four Prolific IDs. Do not reveal or screen on developmental stage in participant-facing materials.
3. In **Data collection**, add the public HTTPS URL of the pilot and select **I'll use URL parameters**. The app reads \`PROLIFIC_PID\`, \`STUDY_ID\` and \`SESSION_ID\`.
4. Configure the Prolific completion URL/code and supply it through \`PILOT_COMPLETION_URL\`.
5. Set compensation consistent with Prolific's current hourly minimum, including time for pre/post questions, reading instructions and possible model latency. Ensure participants know that conversations are being retained for analysis.
6. Run an end-to-end test with a non-production test configuration before publishing. Verify that no conditions are visible in browser responses and that the transcript/ratings survive a server restart.

Prolific instructions for custom allowlists: https://researcher-help.prolific.com/en/articles/445163-how-can-i-invite-specific-participants-to-my-study

Prolific instructions for external study URLs: https://researcher-help.prolific.com/en/articles/445178-what-survey-experimental-software-is-compatible-with-prolific

## 4. Inspect transcripts and outcomes

The database defaults to:

\`\`\`
outputs/prolific_pilot.sqlite
\`\`\`

Read it **only on the researcher's machine**. Example CSV export:

\`\`\`bash
python scripts/export_prolific_pilot.py
\`\`\`

The export is written to \`outputs/prolific_pilot_export_PRIVATE.csv\` and includes treatment, provisional developmental group, pre/post values, timestamps and transcript. Neither this export nor the original SQLite file should ever be committed to this public repository.

## Study interpretation

This pilot can reveal problems with treatment fidelity and differences in natural conversational behavior. It cannot establish a stage × treatment effect with four people. The two groups differ on multiple participant characteristics, and WUSCT labels have not yet received manual-standard confirmation. Freeze model policies and inference settings *before* recruiting, rather than adjusting prompts after reading the experimental results.
